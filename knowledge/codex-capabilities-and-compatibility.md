# Возможности Codex и совместимость

Этот справочник читается по требованию. Он вынесен из корневого `AGENTS.md`, чтобы не расходовать лимит автоматически загружаемой цепочки инструкций.

## Выбор установленной возможности

| Тип задачи | Использовать | Обязательная проверка |
|---|---|---|
| `.xlsx`, `.xls`, `.csv`, `.tsv`, расчёты и табличная аналитика | Spreadsheets; Excel Live Control только при явно подключённой книге | Проверить формулы, единицы, диапазоны и итоговые значения |
| `.docx` и документы для Word/Google Docs | Documents | Отрендерить документ и визуально проверить страницы |
| Чтение, создание или проверка PDF | PDF | Проверить извлечённый текст и визуальный рендер значимых страниц |
| `.pptx`, PowerPoint или Google Slides | Presentations | Проверить структуру, переполнение и визуальный рендер слайдов |
| Графики, сравнения, интерактивные модели и управленческие панели | Visualize | Сверить визуализацию с исходными данными и явно подписать допущения |

Не создавай отдельный новый скилл, если задачу полностью и надёжно покрывает установленная возможность.

## Плагины

Сначала используй подходящую встроенную возможность, затем уже подключённый плагин. Ищи или предлагай новый плагин только тогда, когда задаче действительно нужен внешний сервис, учётная запись или источник данных, недоступный встроенными средствами. Подключение, изменение разрешений, публикация и другие внешние записи требуют подтверждения Юрия.

## Project hooks

Проверка контрактов custom agents задана в `<repo-root>/.codex/hooks.json` и включена через `features.hooks = true`. Runtime-hook должен совпадать с проверенной копией в `evals/epistemic-integrity/hook_entrypoint.py`; эта копия закрепляет SHA-256 канонического валидатора, поэтому изменение логики без изменения и повторной проверки hook приводит к fail-closed остановке.

Project hooks Codex исполняет только в доверенном проекте и после проверки конкретного хеша hook. При первом запуске после установки или изменения открой `/hooks`, просмотри команду и доверь её. Изменение хеша требует повторной проверки. Флаг `--dangerously-bypass-hook-trust` допустим только для изолированного автоматического eval-запуска после успешного `validate_config.py`; не используй его как обычный режим работы.

## Совместимость с навыками Claude Code

Не считай `.claude/skills/` автоматически доступными Codex и не импортируй их массово. Используй следующие замены:

- `discovery-interview` — сфокусированное уточнение требований средствами текущего диалога; без зафиксированной в скилле модели Claude, `AskUserQuestion`, oracle-агентов и жёстких путей;
- `content-creator` — обычные возможности Codex и подтверждённый стиль; для песен только контур Авторской мастерской и `authors-song-workflow`;
- `fullstack-developer` — нативная разработка и проверка Codex без навязывания технологического стека из Claude-скилла;
- `frontend-design` — нативная разработка, Browser и Sites, когда они доступны и соответствуют задаче;
- `reminder` — в Telegram-контуре существующий скрипт напоминаний, а в Codex Scheduled Tasks или подключённый календарь; механизмы не смешивать;
- `server-setup` — следовать актуальной серверной документации проекта и правилам Codex; не переносить как Codex-скилл и не вводить или сохранять root-пароли в командах и файлах.

Плагин Superpowers относится к Claude Code. В Codex его не имитировать и не переносить: использовать встроенное планирование и проверки Codex.
